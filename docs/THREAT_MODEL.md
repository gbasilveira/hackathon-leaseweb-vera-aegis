# Trust model and limitations

Anyone with access to the loopback administration interface acts as the demo operator. Approval actors are selectable lab identities. A request hash binds the approved content. Authentication of an enterprise approver would require an identity provider and session management.

The simulated attack uses local fixture data and grants on synthetic sessions. There is no connector to a cloud management API, Docker daemon or hypervisor. The application shares one OS process and SQLite file across its logical services. Protect the database, scenario directory and local operating-system account. A database administrator can rewrite the evidence.

An instruction embedded in a log has no tool authority. The internal MCP server can inspect, simulate and submit. Only the execution gateway consumes a stored random capability. Approved external read servers can still supply misleading content or observe queries. Configure only trusted server software.

Impact is reverse reachability in the configured graph. Missing organizational relationships can yield incomplete predictions. Global context digests deliberately invalidate grants on unrelated state changes. Session suspension semantics belong to the simulator. The transaction boundary ends at SQLite.
